# Wireframes

## Purpose

Describe the screen structure for the Antwerp journey before implementation.

## Goals

- Keep the MVP mobile-first.
- Identify required screens and primary actions.
- Avoid over-designing before playtesting.
- Give implementation a shared layout vocabulary.

## Initial Screen List

### Resume / Start

Primary actions:

- Resume active journey.
- Start a new journey.
- Open route notes only if needed.

### Antwerp Map

Primary zones:

- Current position.
- Next location.
- Completed locations.
- GPS status.

### Active Location

Primary zones:

- Location name.
- Arrival status.
- Dice prompt.
- Resource outcome preview.

### Dice Entry

Primary zones:

- Roll total.
- Validation message.
- Confirm button.

### Resource Update

Primary zones:

- Resource changes.
- Updated totals.
- Continue button.

### Journey History

Primary zones:

- Chronological route events.
- Location filter.
- Correction action.

## Open Questions

- Should the map be the home screen or a dedicated live route view?
- Should dice entry be fixed at the bottom of the screen?
- Should history be reachable from every screen?

## Future Improvements

- Low-fidelity sketches.
- Interactive prototype.
- Landscape route mode.
